This document records the research increment for GitHub issue #331. It does not introduce a
cleanup implementation and does not claim that the issue is complete.

== Production inventory

The following command finds three `finalize()` overrides in production sources:

[source,bash]
----
rg -n "void finalize\(\)" src/main/java
----

[cols="1,2,2"]
|===
|Location |Purpose |Migration requirement

|`CleaningRandomAccessFile`
|Best-effort close when the caller omitted explicit close
|Preserve descriptor release without a cleanup action that strongly references the file owner

|`AbstractCloseable.Finalizer`
|Warn and close a leaked closeable
|Preserve both warning and close behaviour using owner-free cleanup state

|`CloseableUtils.gcAndWaitForCloseablesToClose()`
|Test and diagnostic barrier that waits for the JVM finaliser thread
|Replace separately once production cleanup no longer depends on finalisation
|===

== Measured disabled-finalisation behaviour

The observations below were recorded on 2026-08-22 with OpenJDK 21.0.11. The complete probe is
committed as `src/test/java/net/openhft/chronicle/core/io/FinalisationDisabledProbe.java`. It is a
manual research aid rather than a unit test because GC timing is nondeterministic and the disabled
case requires a JVM launch flag.

Compile the test sources and write their dependency class path to a durable file:

[source,bash]
----
mvn -q -DskipTests test-compile dependency:build-classpath \
  -Dmdep.outputFile=target/test-classpath
----

On Unix-like systems, set the probe class path and run the two finaliser invocations:

[source,bash]
----
PROBE_CP="target/test-classes:target/classes:$(cat target/test-classpath)"
java -cp "$PROBE_CP" net.openhft.chronicle.core.io.FinalisationDisabledProbe
java --finalization=disabled -cp "$PROBE_CP" \
  net.openhft.chronicle.core.io.FinalisationDisabledProbe
----

[cols="1,1"]
|===
|Invocation |Result

|`java FinalizeProbe`
|`finalize ran = true`

|`java --finalization=disabled FinalizeProbe`
|`finalize ran = false`
|===

The same committed probe calls `AbstractCloseable.gcAndWaitForCloseablesToClose()` when passed the
`barrier` argument:

[source,bash]
----
java -cp "$PROBE_CP" net.openhft.chronicle.core.io.FinalisationDisabledProbe barrier
java --finalization=disabled -cp "$PROBE_CP" \
  net.openhft.chronicle.core.io.FinalisationDisabledProbe barrier
----

[cols="1,2"]
|===
|Invocation |Result

|Default finalisation
|Returned normally in approximately 334 ms

|`--finalization=disabled`
|Threw `AssertionError: Timed out waiting for the Finalizer` after approximately 5,382 ms
|===

This demonstrates a hard dependency in the diagnostic barrier. It does not prove that the two
production safety nets can be removed: existing happy-path tests close resources explicitly and
therefore do not exercise forgotten-close behaviour.

== Required follow-up proof

The next implementation increment must:

* keep its reference and worker implementation private;
* migrate one production finaliser rather than publish an unused abstraction;
* prove explicit cleanup exactly once with deterministic queue processing;
* prove automatic resource release with `--finalization=disabled`;
* ensure the cleanup action cannot retain its owner;
* define interruption, termination and context-class-loader behaviour; and
* retain raw commands and results with the change.

The `CloseableUtils` barrier is a separate test-infrastructure migration. It must not be treated as
evidence that either production safety net is safe to delete.
