= Chronicle Core - Requirements Specification
:toc:
:sectnums:
:lang: en-GB
:source-highlighter: rouge

This document captures all *CORE*-scoped requirements for the Chronicle Core library.
Requirement identifiers follow the company-wide *Nine-Box* taxonomy:

<Scope>-<Tag>-xxx   ->   CORE-FN-001, CORE-NF-P-006, ...

Only the primary tag is shown when several could apply.
All numbers are unique within the *CORE* scope.

== Requirement Catalogue

=== Operating-System Abstraction Layer

CORE-FN-001 :: The system shall allow retrieval of the Process ID (PID) of the current Java process.
CORE-FN-002 :: The system shall allow determination of the operating-system type (Windows, Linux, macOS) and architecture (32- or 64-bit).
CORE-FN-003 :: The system shall allow retrieval of the system host-name and the current user-name.
CORE-FN-004 :: The system shall allow retrieval of the operating-system page size.
CORE-FN-005 :: The system shall allow retrieval of the path to the temporary directory.
CORE-FN-006 :: The system shall provide a method to map a specified region of a file into memory.
CORE-FN-007 :: The mapping functionality shall support read-only and read-write access modes.
CORE-FN-008 :: The system shall provide a method to unmap a previously mapped memory region.
CORE-FN-009 :: The system shall provide an accessor that returns an implementation of the `Memory` interface.

=== JVM Interaction Layer

CORE-FN-010 :: The system shall allow querying whether the JVM is running in debug mode.
CORE-FN-011 :: The system shall allow querying the current and maximum direct-memory usage.
CORE-FN-012 :: The system shall allow determination of the JVM bitness (32- or 64-bit).
CORE-FN-013 :: The system shall provide enhanced parsing for boolean system properties.
CORE-FN-014 :: The system shall automatically load `system.properties`, with an override via `-Dsystem.properties=<file>`.
CORE-FN-015 :: The system shall support execution of user-defined code *before* Chronicle reads any system properties (`chronicle.init.runnable`).
CORE-FN-016 :: The system shall support execution of user-defined code *after* `Jvm` static initialisation (`chronicle.postinit.runnable`).
CORE-FN-017 :: The system shall provide a utility to rethrow checked exceptions as unchecked.
CORE-FN-018 :: The system shall provide methods to access class-memory-layout metrics.
CORE-FN-019 :: The system shall provide microsecond-precision busy-wait methods.
CORE-FN-020 :: The system shall provide methods to interact with JVM safepoints.
CORE-FN-021 :: The system shall provide methods to configure custom exception handlers for fatal, warn, debug, and perf severities.

=== Low-Level Memory Access

CORE-FN-022 :: The system shall provide methods to *read* each Java primitive type from a native-memory address.
CORE-FN-023 :: The system shall provide methods to *write* each Java primitive type to a native-memory address.
CORE-FN-024 :: The system shall provide compare-and-swap (CAS) operations for 32-bit integers at a native address.
CORE-FN-025 :: The system shall provide compare-and-swap (CAS) operations for 64-bit long integers at a native address.
CORE-FN-026 :: The system shall provide atomic-addition operations for integer types at a native address.
CORE-FN-027 :: The system shall provide methods for *volatile* reads of primitive types from native memory.
CORE-FN-028 :: The system shall provide methods for *volatile* writes of primitive types to native memory.
CORE-FN-029 :: The system shall provide load-, store-, and full-fence memory-ordering operations.

=== Deterministic Resource Management

CORE-FN-030 :: The system shall provide `AbstractCloseable` to define deterministic cleanup actions.
CORE-FN-031 :: Closeable resources shall track and expose their closed state.
CORE-FN-032 :: Closeable resources shall prevent or signal errors on use-after-close.
CORE-FN-033 :: The system shall support capturing diagnostic information (e.g. stack traces) for resource-misuse debugging.
CORE-FN-034 :: The system shall provide `ReferenceCounted` for resources managed by reference counting.
CORE-FN-035 :: Reference-counted resources shall allow *reserve* operations to increment their count.
CORE-FN-036 :: Reference-counted resources shall allow *release* operations to decrement their count.
CORE-FN-037 :: Resource deallocation/closure shall occur only when the reference count reaches zero.
CORE-FN-038 :: The system shall allow tracking of reference owners for debugging.
CORE-FN-039 :: The system shall optionally defer resource deallocation to a background thread.

=== Concurrency & Threading Support

CORE-FN-040 :: The system shall provide a mechanism for components to declare single-threaded access requirements (`SingleThreadedChecked`).
CORE-FN-041 :: Single-threaded components shall perform runtime checks for concurrent-access violations.
CORE-FN-042 :: The single-threaded check shall be resettable to enable safe thread hand-off.
CORE-FN-043 :: The library shall document and support the *initialise -> reset -> hand-off* pattern for such objects.

=== Low-Level Utilities

CORE-FN-044 :: The system shall provide mechanisms for pooling and reusing `String` instances.
CORE-FN-045 :: The system shall provide mechanisms for efficiently obtaining `Enum` instances from string representations.
CORE-FN-046 :: The system shall provide `ClassLocal<T>` for lazy initialisation and caching of objects per class.
CORE-FN-047 :: `ClassLocal` initialisation shall be definable via a lambda or supplier.
CORE-FN-048 :: The system shall provide utility methods for allocation-free mathematical operations.
CORE-FN-049 :: The system shall provide utility methods for optimised hashing.
CORE-FN-050 :: The system shall provide functional interfaces that extend `java.io.Serializable` for serialisable lambdas.
CORE-FN-051 :: The system shall provide a histogram implementation optimised for low-overhead value recording.
CORE-FN-052 :: The histogram shall support a wide dynamic range (nanoseconds -> seconds).
CORE-FN-053 :: The histogram shall allow configurable precision or accuracy.

=== Interfaces & Dependencies

CORE-FN-054 :: Chronicle Core APIs consumed by other Chronicle libraries shall be designed for long-term stability.
CORE-FN-055 :: Evolution of Core APIs shall minimise breaking changes for dependent libraries.

=== Non-Functional Requirements – Performance (CORE-NF-P-*)

CORE-NF-P-001 :: Core hot-path operations (for example OS and JVM capability lookups, `Memory` / `UnsafeMemory` primitive access, and `SingleThreadedChecked` guards) shall avoid heap allocation after warm-up under normal operating conditions.
CORE-NF-P-002 :: When resource tracing is disabled, the additional CPU and allocation overhead introduced by tracing-related code paths shall be negligible for representative workloads, in line with the expectations of `CORE-OPS-004` in `operational-requirements.adoc`.
CORE-NF-P-003 :: Enabling `BackgroundResourceReleaser` shall move heavy deallocation work off application hot paths so that dependent modules can continue to meet their own latency and jitter targets, as documented in their performance requirements and in `performance-targets.adoc`.
[[CORE-NF-P-006]]
CORE-NF-P-006 :: The library shall provide a monotonic microsecond-resolution time provider (`UniqueMicroTimeProvider`) that guarantees strictly increasing values within a single JVM while keeping worst-case drift and latency within the bounds described in `unique-micro-time-provider-cas-loop.adoc`.

=== Non-Functional Requirements – Security (CORE-NF-S-*)

CORE-NF-S-001 :: Core memory-access and resource-management APIs shall either perform appropriate bounds and state checks or clearly document where callers are responsible for validating inputs before use, as described in `security-review.adoc`.
CORE-NF-S-002 :: Use of internal JDK APIs and `sun.misc.Unsafe` shall be encapsulated behind Chronicle Core abstractions (for example `Memory`, `UnsafeMemory`), with risks, mitigations and required JVM flags documented in `security-review.adoc`.
CORE-NF-S-003 :: File-mapping operations shall support and honour the `chronicle.core.mmap.allowedDirs` system property such that attempts to memory-map files outside the configured directories fail with a security-focused exception, in line with decision `CORE-RISK-003`.
