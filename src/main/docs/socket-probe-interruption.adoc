= Preserve interruption during regional socket probing
:sectnums:

The first `IOTools.isClosedException` lookup in a non-English locale gathers local
socket error messages. This diagnostic initialisation must preserve an incoming
interrupt and must not leave an interrupt generated by the probe on the caller.
An entry interrupt is temporarily cleared before opening or accepting channels
and restored in `finally`, including when acquisition or resource cleanup fails.

The interrupted-write case sets the probing thread's flag immediately before a
blocking channel write. Java's `InterruptibleChannel` contract specifies that
this closes the channel and throws `ClosedByInterruptException`, just as an
interrupt during a blocked operation does. Clearing the probe's own flag before
resource cleanup removes the need for a delayed interrupter worker. There is no
worker that can deliver an interrupt after the lookup returns.

The separate asynchronous-close probe remains. Its worker stays outside the
`Language` class to avoid blocking on the class initialiser that is waiting for
its socket operation. It no longer writes an unsolicited message to standard output.

`IOToolsLocaleInterruptionTest` invokes the real public lookup in separate French
locale JVMs for both entry states. It checks message collection, status on return
and completion without late interruption. Child processes are bounded and cleaned
up even on failure. `IOToolsTest.connectionClosed4` directly checks the interrupted
write exception and restores its own status outside resource cleanup.
These tests do not inject a native socket-close failure.

This is a behavioural extraction from
https://github.com/OpenHFT/Chronicle-Core/pull/846[#846], without its annotation scheme.
See the https://docs.oracle.com/javase/8/docs/api/java/nio/channels/InterruptibleChannel.html[Java channel contract].
